# 进度

## 0.1.0 后端骨架（2026-11-08，等合并）

- 起因：ray 决定不在算力门仓库里加模块，另起这个仓库从零搭独立平台；要求先把数据库和接口设计完再开发，前端页面要先给 3 个方案选。
- 技术路线：FastAPI + PostgreSQL 做控制面；开源 New API 做转发引擎（卖方 Key = 渠道，买方 = 用户 + 令牌，用量从日志同步）。原设计稿里「自己写网关」的部分改为驱动 New API，路由评分 / 预留余额 / 失败切换由引擎的优先级、额度、自动禁用承担。
- 已实现（接口按 docs/openapi.yaml，少数字段按实现调整）：
  - 认证：注册 / 登录 / 我；JWT；买方注册即在引擎建用户。
  - 卖方：入驻申请与后台审核；Key 托管（引擎校验 → 渠道）、挂单（结算折扣驱动渠道模型列表与优先级）、定价参考、收益、用量、结算单、提现、保证金、求购单浏览。
  - 买方：子密钥（引擎令牌）、钱包、充值单与审核（首充送 10%）、用量与汇总、求购单。
  - 后台：看板、用户、卖方审核、充值审核、厂商 / 模型 / 售价规则、定价推送、Key 与挂单管理、结算生成 / 冻结、扣款、提现审核（看得到完整收款账号）、保证金登记、参数、动态（手工发的默认带演示角标）、审计、引擎状态、手动触发同步 / 探活、演示数据装卸。
  - 公开：市场模型与售价、模型详情 / 健康度、首页数字（含 `includes_demo`）、动态、求购。
  - 后台任务：用量同步（按日志 id 游标）、探活（连续失败判死、恢复复活、信用加减）、每日结算与到期转可提现。
  - 命令行：migrate / create-admin / seed-demo / clear-demo / sync-usage / probe-keys / settle / sync-pricing / gateway-status。
  - 自动测试 11 项（含完整交易闭环：定价 → 充值 → 密钥 → 调用 → 同步 → 结算 → 提现），仿 New API 在 tests/fake_newapi.py。
  - docker-compose（postgres / redis / mysql / new-api / api / nginx）、nginx 配置、Dockerfile。
- 设计稿里暂未做 / 简化：
  - 买方等级定价（`buyer_tier`）：表和规则有，接口只用全局 / 模型级。
  - Key 交付担保订单（`delivery_orders`）、纠纷（`disputes`）、硬件专区：建了表，没有接口。
  - 视频模型按秒计费：引擎按次扣费，秒数按默认 5 秒估算；等接视频任务回调再精确。
  - 卖方每日上限 `daily_cap_usd`：记了用量，还没有到上限自动停渠道。
  - 买方子密钥的消费上限 / RPM：存了字段，引擎侧没下发。
  - 通知（卖方 Key 失效、买方余额不足）：没有。
